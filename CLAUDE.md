## What this app is

A centralized company SSO login portal (frontend only — identity is provided by a self-hosted [Authentik](https://goauthentik.io/) instance, not by any backend in this repo). Other internal services redirect unauthenticated users here; after login this app hands a token back to the originating service.

Login flow:
1. A service redirects the user to `/login?redirect_uri=<originating service URL>`.
2. `/login` (`app/login/page.tsx`) captures `redirect_uri` into `sessionStorage` via `lib/redirect.ts`, but only if it passes an allowlist check (`isAllowedRedirectUri`) — this exists specifically to prevent open-redirect abuse of the token handoff.
3. User clicks the single login button (`components/AuthentikLoginButton.tsx` → `lib/authentik.ts#startAuthentikLogin`), which runs a standard **OAuth Authorization Code + PKCE** flow (RFC 7636) directly against Authentik — no backend of ours is involved:
   - This app is registered in Authentik as a **Public client** (no client secret — a secret can't be kept safe in browser-shipped JS). `lib/pkce.ts` generates `code_verifier`/`code_challenge` via Web Crypto; both `code_verifier` and a CSRF `state` are stashed in `sessionStorage`, then the browser is redirected to Authentik's `authorization_endpoint`.
   - Authentik redirects back to `app/auth/authentik/callback/page.tsx` with `code`/`state`. The callback strips them from the URL immediately (`history.replaceState`, since the code is single-use), guards against React double-invoking the effect with a `useRef` flag, then `lib/authentik.ts#completeAuthentikLogin` re-validates `state` and POSTs to Authentik's `token_endpoint` (with `code_verifier`, no secret) to get back `id_token` — that's the credential this app hands off, deliberately not `access_token` — downstream services only need to know *who* logged in (verifiable via Authentik's JWKS), not to call an API on the user's behalf.
4. On success, `lib/redirect.ts#completeLoginWithToken` reads back the allowlisted `redirect_uri` and navigates there with the `id_token` in the **URL fragment** (`#token=...`), not a query param — this is intentional so the token never hits server access logs or gets leaked via `Referer`. If no valid pending redirect exists, it falls back to `/login/success`, a static "you're logged in" page for when someone opens the portal directly.

Authentik endpoints/client id are configured via `NEXT_PUBLIC_AUTHENTIK_AUTHORIZATION_ENDPOINT`, `NEXT_PUBLIC_AUTHENTIK_TOKEN_ENDPOINT`, `NEXT_PUBLIC_AUTHENTIK_CLIENT_ID` (see `.env.local.example`). `lib/authentik.ts` fails fast at import time if any is unset.

`NEXT_PUBLIC_ALLOWED_REDIRECT_HOSTS` (comma-separated domain suffixes, e.g. `.company.com`) is the open-redirect allowlist consumed by `lib/redirect.ts`. If unset, no cross-domain redirect is ever allowed and users always land on the local success page — treat this as a safety default, not a bug.

## Conventions in this codebase

- UI copy and code comments are written in Traditional Chinese (zh-TW). Match this when editing existing files.
- This is Next.js 16 (App Router) — see `AGENTS.md` for why you must check `node_modules/next/dist/docs/` before assuming API behavior from training data. Notably: route props use the generated global `PageProps<'/route'>` / `LayoutProps<'/route'>` helpers (see `app/layout.tsx`) instead of hand-written prop types; these types are (re)generated by `next dev`/`next build`/`next typegen` and require no import.
