## What this app is

A centralized company SSO login portal (frontend only — the actual auth backend is a separate, pre-existing service). Other internal services redirect unauthenticated users here; after login this app hands a token back to the originating service.

Login flow:
1. A service redirects the user to `/login?redirect_uri=<originating service URL>`.
2. `/login` (`app/login/page.tsx`) captures `redirect_uri` into `sessionStorage` via `lib/redirect.ts`, but only if it passes an allowlist check (`isAllowedRedirectUri`) — this exists specifically to prevent open-redirect abuse of the token handoff.
3. User authenticates via either:
   - **Microsoft 365 OAuth** (`components/MicrosoftLoginButton.tsx` → `lib/ssoApi.ts#getMicrosoftLoginUrl` → redirect to Microsoft → `app/auth/microsoft/callback/page.tsx` exchanges `code`/`state` via `exchangeMicrosoftCallback`). OAuth `state` is round-tripped through `sessionStorage` and validated on callback to prevent CSRF. The callback strips `code`/`state` from the URL immediately (`history.replaceState`) since the code is single-use, and guards against React double-invoking the effect with a `useRef` flag.
   - **Username/password** (`components/PasswordLoginForm.tsx` → `lib/ssoApi.ts#passwordLogin`). The backend endpoint/response shape for this is still unconfirmed (see TODO in `lib/ssoApi.ts`) — check with the backend team before relying on its error format.
4. On success, `lib/redirect.ts#completeLoginWithToken` reads back the allowlisted `redirect_uri` and navigates there with the token in the **URL fragment** (`#token=...`), not a query param — this is intentional so the token never hits server access logs or gets leaked via `Referer`. If no valid pending redirect exists, it falls back to `/login/success`, a static "you're logged in" page for when someone opens the portal directly.

All backend calls go through `lib/ssoApi.ts`, which talks to `NEXT_PUBLIC_SSO_API_BASE_URL` (existing SSO backend, not part of this repo; endpoints: `/auth/microsoft/login`, `/auth/microsoft/callback`, `/auth/login`). This module throws at import time if the env var is unset, so any page importing it will fail hard without a `.env.local` (copy from `.env.local.example`).

`NEXT_PUBLIC_ALLOWED_REDIRECT_HOSTS` (comma-separated domain suffixes, e.g. `.company.com`) is the open-redirect allowlist consumed by `lib/redirect.ts`. If unset, no cross-domain redirect is ever allowed and users always land on the local success page — treat this as a safety default, not a bug.

## Conventions in this codebase

- UI copy and code comments are written in Traditional Chinese (zh-TW). Match this when editing existing files.
- This is Next.js 16 (App Router) — see `AGENTS.md` for why you must check `node_modules/next/dist/docs/` before assuming API behavior from training data. Notably: route props use the generated global `PageProps<'/route'>` / `LayoutProps<'/route'>` helpers (see `app/layout.tsx`) instead of hand-written prop types; these types are (re)generated by `next dev`/`next build`/`next typegen` and require no import.
